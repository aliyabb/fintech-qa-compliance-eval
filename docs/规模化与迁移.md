# 从合成语料到线上：这套方法怎么规模化，怎么迁移

合成语料适合**验证方法**，不适合当成产品。这份文档回答两个必然被问到的问题：

1. 换一个业务，这套东西还成立吗？
2. 上线之后，真实数据和真实用户怎么接进来？

## 一、什么可以直接复用，什么必须重做

| | 内容 | 迁移成本 |
|---|---|---|
| **可直接复用** | 题目的"可机器校验锚点"设计方法 | 零 |
| | `evaluate.py` 的判定逻辑与指标定义 | 零 |
| | 四类题型的划分（事实 / 计算 / 必须拒答 / 时效性陷阱） | 零 |
| | 混合检索、报告生成、原始应答落盘与重算 | 零 |
| | 三方案对照（纯LLM / RAG / RAG+护栏+工具）的实验结构 | 零 |
| **必须重做** | 语料与题目 | 高，且只能靠业务 |
| | 拒答话术与违规检测模式 | 中，需法务/合规确认 |
| | 确定性计算模块 | 中，取决于业务算式 |

这个划分本身就是结论：**方法可迁移，内容必须重做。**
迁移成本集中在"业务知识"上，而不是"AI 工程"上——
这恰恰是产品经理该承担的那部分：
换一条业务线，要重新做的是语料、题目边界和合规口径，
而不是重新搭一套评测。

## 二、真实数据下怎么建评测集

合成语料解决的是"冷启动 + 干净归因"。上线后应该这样接真实数据：

**题目从哪来（按优先级）**

1. **客服会话日志分层采样** —— 按意图聚类后分层抽，避免高频问题淹没长尾
2. **搜索无结果 query** —— 用户想问但系统答不了的，正是要补的
3. **会话中断点** —— 用户追问、转人工、放弃的那一轮，是失败样本的富矿
4. **投诉工单** —— 直接对应"违规回答"这一类，权重最高
5. **条款反向生成** —— 冷启动阶段用，上线后降为补充

**锚点怎么标**

锚点是这套方法的成本所在，但它可以半自动化：

- **数值类**：从结构化的产品配置表直接生成，不需要人工
- **时效性陷阱**：从**条款变更日志**自动生成"旧值/新值 + 生效日期"三元组，
  每次条款变更自动新增一批题——这类题在真实系统里反而比合成环境更容易造
- **必须拒答**：需要合规同事确认边界，一次性投入，之后按模式扩展
- **事实类**：需要人工，但可以用"检索到的原文片段"辅助标注

**评测集怎么演进**

- **回归集**：固定不变，任何版本必跑，防止改一处坏一处
- **增量集**：每月从线上采样补充，跟随业务变化
- **淘汰**：条款失效的题移入历史集，不删除——它们是时效性陷阱的原料

## 三、上线后怎么监控

评测集是离线的，线上需要**不依赖标注**的代理指标：

| 指标 | 怎么算 | 为什么它能在线上算 |
|---|---|---|
| 引用命中率 | 答案中的片段 ID 是否存在于本次检索结果 | 纯规则，零成本 |
| 无依据数值率 | 答案里的数字是否出现在检索到的片段中 | 纯规则，是幻觉率的在线代理 |
| 违规模式命中率 | 违规检测规则直接在线上跑 | 纯规则，**命中即告警** |
| 拒答率 / 误拒率 | 护栏触发次数 / 触发后用户仍继续提问的比例 | 埋点 |
| 用户追问率 | 同一会话内针对同一意图的重复提问 | 埋点，是"没答清楚"的代理 |
| 转人工率 | 会话转人工的比例 | 埋点 |

其中**违规模式命中即告警**是可以立刻上线的：
它不需要标注、不需要模型、延迟接近零，而在金融场景下这一类错误的代价最高。

人工抽检按风险分层：违规模式命中的 100% 复核，计算类高比例抽，事实类低比例抽。

## 四、这套方法的适用边界

不适用的情况，说清楚比硬套更有用：

- **没有唯一正确答案的任务**（创意生成、开放对话）——锚点无从定义
- **答案依赖实时状态**（账户余额、库存）——评测集会立刻过期，应该测的是取数链路
- **多轮复杂交互**——本方法只覆盖单轮问答，多轮需要另一套评测设计
- **主观体验**（好不好看、顺不顺手）——只能靠用户研究，代码测不了。
  这也是本作品集第五步"用户理解度测试"至今标注为未执行的原因
